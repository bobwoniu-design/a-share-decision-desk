# 短线决策台 v0.5

A股人工决策辅助工作台。提供桌面优先的真实行情决策引擎、持久交易日志、每日复盘、个人统计、手工事件和自选名单。没有交易委托能力。

## P0 决策引擎

- 市场：近20交易日，赚钱广度25%、涨跌停平衡15%、封板稳定10%、昨日涨停溢价15%、晋级15%、高度10%、成交活跃10%；连板晋级分母为前一日涨停，分子为今日再次收盘涨停且至少2板。高位样本为昨日≥3板，展示匹配覆盖。昨日溢价样本不足90%不计算。
- 板块：全行业成员参与统计。持续性25%、相对强度25%、成交活跃20%、梯队15%、抗分歧15%；显示前日分差和阶段历史。至少3只有行情且覆盖80%，已知权重≥80%才输出综合分。75分且前5日相对涨幅前十≥3次标主线，65分为主线候选。当前为行业代理，不宣称覆盖玻璃基板等概念题材。
- 核心：板块25%、梯队20%、成交占位20%、相对强势20%、5日趋势15%；角色均标“候选”，展示依据。TOP10来自板块及核心度均≥65、当日上涨的成员，每板块最多3只。日线收益链用逐日pct，缺日不补收益。
- 分钟：按时间前缀顺序计算一致/分歧/承接/转强/加速/转弱。20根完整分钟后才生成条件，2次连续满足才正向转换；缺失不补分钟，不把午休算缺口；官方零成交分钟可维持站线计数，但无当分钟成交不生成正向提示；一字涨停可识别一致，不虚构分歧买点。观察前高到当前价的有序回撤，不用无序最高最低振幅充当回撤。
- 盘中同步：在前一交易日冻结同业至多6只独立样本，排除当前个股；至少3只且80%同分钟数据完整，才输出板块共振。展示样本及失败信息。不能用一只票代表整个行业。
- 条件链：前一日市场≥45且风险非高（实时模式同时要求当前全市场条件允许）、板块≥65、核心≥65为观察基础。第一笔=承接且板块不弱；第二笔=价格确认且板块同步；第三笔=放量突破且同步。风险/逻辑失效优先；不计算建议买入数量，也不下单。
- 历史回放将当前游标之后的数据完全排除。盘后日线排名单独标记，不用于反推当天交易资格。分钟图和日K下均保留当前分钟状态与条件核对。
- 今日盘中：服务端使用rt_k+stk_limit估算盘中市场快照，使用rt_min_daily获取已结束分钟。原始实时缓存45秒；页面可见且交易时段每60秒刷新，收盘后或页面隐藏不自动请求；权限错误停止对应自动轮询。日期错误、全市场覆盖不足90%、时间落后超过2个交易分钟不会伪装成实时结果。盘中成交总额不与完整日均额直接比较。历史模式维持stk_mins，缓存24小时。
- 股本：前一日daily_basic.float_share（万股）×10000，计算估算累计换手；股本可能变化，因此不作为强制买点。成交量为股、成交额为元，资金活跃不是净流入。
- API /api/market/decision 只读共享市场输入。个人账本/复盘的鉴权、数据和模型保持原样；无新存储表。状态时间线由相同输入和版本重算，版本P0.1。

规则阈值在lib/decision-engine.ts和lib/minute-engine.ts集中定义。37项测试覆盖因果前缀一致性、缺失与过期门控、板块覆盖、六阶段和辅助条件、晋级口径、单位、行情与账本回归。

## 板块与图表更新

- 行业全景：以 stock_basic 当前行业分类合并全市场日线和涨跌停名单，含所选日已上市的 L/D/P 股票；按上市、退市日期筛选。行业分类变更未还原，不冒充历史题材成员。成员列表不受20只观察池限制，支持搜索、分页、涨跌/成交额排序及无行情筛选。
- 展示等权平均涨幅、涨跌平家数、无行情覆盖率、涨跌停/炸板及成交额。龙头/龙二/龙三为上涨非ST股票按连板高度→当日涨幅→成交额排序的候选，并单列成交额第一；不是已验证的龙头认定。
- 60日日K使用真实开高低收并统一前复权，下面对齐原始成交额/成交量柱，可切换；显示5根有效日线均值和当日成交额/前5根均额。成交量单位手，金额从千元转换为亿元，不作为净流入。
- 停牌查询仅在日线缺失时调用 suspend_d；只有相同日期的全天停牌记录才标停牌，其他缺口继续标为数据缺失。日K和成交柱均不插值。
- 桌面压缩导航、卡片、间距；情绪历史和观察池默认折叠，板块全景与个股图优先。

## 本次历史扩展

- 市场轨迹默认20个交易日，可切换7日，展示涨跌停、沪深成交额、昨日涨停溢价与逐日表；行业涨停数前三出现频次用于持续性观察。
- 任意A股、持仓与自选可读取60个交易日日线。daily原始收盘用于报价；adj_factor以窗口最后一条行情为基准前复权，用于5/20交易日涨幅与5/20根有效日线均线。缺因子不计算跨日指标，缺日不补值。
- 分时可切换最近7个交易日，VWAP每天重新累计，涨跌基准使用该日daily的pre_close。
- `/api/market/context`仅访问共享市场数据，权限边界与history接口相同。日期窗口由SSE交易日历确定并截止所选日，无未来数据。
- 截图持仓属于期初快照，不还原未知成交时间、历史手续费或既往已实现盈亏；基金161125暂不纳入。

## 已实现

- 决策引擎：市场情绪、行业主线评分、核心度、六阶段分钟状态、同分钟板块样本联动、条件提示和失效检查。
- 真实账本：手工成交/期初持仓、详情更正、软撤销、标准CSV预览导入及去重、CSV导出。按含费移动平均成本核算部分卖出与完整平仓周期。
- 每日复盘：逐日成交/持仓/费用汇总，个人笔记，草稿/确认，历史版本，文本导出。无交易日同样可记录。
- 个人统计：已实现盈亏、已平仓胜率、平均盈亏比、已平仓金额曲线、模式/自评分组。
- 事件与自选：手动来源链接、摘要、核实状态，观察名单。
- 持久化：D1按用户隔离、修订号并发保护、操作日志、JSON备份和空账本恢复；无浏览器存储依赖。
- Tushare服务端历史分钟查询接口与页面：配置密钥后可查询指定股票和日期，页面处理未配置/无权限/无行情/超时。密钥不进入客户端。

## 明确边界

首页默认读取 2026-09-30 的真实Tushare历史数据，支持日期切换。使用 daily（沪深北涨跌家数、沪深股票成交额）、limit_list_d（不含ST涨跌停、连板、炸板、按当日行业涨停数排名）、trade_cal（上一交易日）、stock_basic（非涨停股的当前名称）和 stk_mins（所选股票历史分钟）。历史数据在D1缓存24小时；错误与空返回不缓存。缺失数据不使用示例替代。

涨停溢价为前一交易日涨停股票在所选日期有日线样本的等权收盘涨幅，展示有效/全部样本数。候选池为连板高度前8名和上涨成交额前列的去重合并，最多20只，仅用于事后复盘。自动评分、周期和角色均为可解释的规则候选。板块分钟样本覆盖不足时不输出同步确认；这套规则尚未完成策略回测或收益验证。

`/api/market/history` 是私有站点的共享市场数据读取/缓存接口，不访问任何个人账本；由Sites dispatch的私有访问策略及平台服务凭证保护。提供日期可选股票代码查询，允许授权服务访问来核验数据入库。个人账本端点继续校验用户ID和同源写入。站点保持仅所有者访问，不能将服务凭证放入客户端。

复盘摘要为规则汇总，不调用AI模型；打开页面时生成，没有无人值守定时任务。新闻需手动录入，未接新闻抓取。尚无截图附件、交易点叠加真实分时、分红送股调整、完整资金流与账户收益率/回撤。盈亏不是账户当日收益。

本地开发库与线上D1库完全独立；本地验收数据不会上传。首次线上使用为空账本。

## 本地运行

需要 Node.js >=22.13，保留 package-lock.json。

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_burly_wolverine.sql
npm run dev
```

只在新本地库执行迁移一次。开发服务默认使用127.0.0.1:5173；自带仅限本地的模拟登录，线上使用平台登录。可在本地 `.dev.vars` 设置 TUSHARE_TOKEN；线上通过Sites密钥配置设置同名值，不要提交密钥文件。`.env.example`仅记录变量名。
